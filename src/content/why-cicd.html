Why CI/CD on z/OS?

MainframeGuru editorial

The reasons for switching are rarely purely technical. Usually the skills situation, company-wide standardization, speed, quality and compliance all come together. Here are the main drivers – each with publicly documented examples.

Skills · One standard: Git · Speed · Quality & testing · Compliance · Cost · AI · Risks · FAQ

1. Skills and developer experience

In the BMC Mainframe Survey 2025, millennials make up 51% and Gen Z 15% of respondents (BMC).

MainframeGuru editorial

People trained on Git, VS Code and pull requests find it hard to work with ISPF-centric library manager processes. Uniform tools across all platforms make knowledge transferable and shorten onboarding time.

Real-world example: UBS has been training its own junior staff for years and relies on Git, GitLab, CI/CD and modern IDEs so that COBOL developers use the same processes as colleagues on other platforms (Legacy IT Center, in German).

2. One standard for the whole enterprise

MainframeGuru editorial

Git is the de facto standard for version control. Keeping mainframe code in the same system enables shared reviews, security scans, permission and audit models, and cross-platform releases.

IBM argues that Git should be the authoritative source for code, pipeline definitions and configuration – rather than being permanently synchronized with a legacy library manager (Planet Mainframe). Broadcom, BMC and Rocket offer coexistence options (Endevor Bridge for Git, Code Pipeline with Git, ChangeMan Git integration) – see Migrations.

3. Speed and parallel development

  • ANZ Bank: hotfixes that used to mean around four weeks of effort for retrofit and deployment now take one hour at most, according to an IBM case study (IBM).
  • Nedbank: build-to-production reduced from hours to around 18 minutes, deployment cycles from 2–3 months to around 3 weeks (BMC).
  • Incremental builds: dependency-based builds compile only what changed and what is affected – a BMC internal team reports a reduction from around 90 to 3 minutes (BMC).
MainframeGuru editorial

Branches instead of check-out/check-in allow several developers to work on the same program at the same time.

4. Quality through automated testing

According to the vendors, IBM Test Accelerator for Z 3.0 generates and runs COBOL unit tests with AI assistance, and BMC AMI DevX Unit Test (beta) generates test data from COBOL sources. Integration tests against real z/OS systems can be automated with the open-source framework Galasa, static analysis e.g. with SonarQube (COBOL).

MainframeGuru editorial

In a pipeline, these become quality gates.

5. Compliance and traceability

MainframeGuru editorial

Regulated industries need a complete trail from the business change to the module in production. Modern toolchains provide this through commit history, pull request approvals, build metadata (e.g. DBB build maps), SBOMs (e.g. Broadcom sbomz) and deployment evidence (e.g. Wazi Deploy, which from 3.0.8 can also store it in Db2).

According to a guest article by IKAN on TechChannel, Git “does not manage the complete application lifecycle” (TechChannel).

6. Cost and tool landscape

The ANZ case study cites license-cost savings of around 90% compared with its previous mainframe SCM (IBM). The figure comes from a vendor source.

MainframeGuru editorial

New costs arise for build/deploy tools, pipeline infrastructure, migration and training.

7. AI needs modern pipelines

In 2026, IBM (Bob Premium Package for Z, Pipeline Automation for Z) and BMC (Code Pipeline MCP Server) announced AI features for mainframe development; Rocket announced AI-assisted code explanation in November 2025.

MainframeGuru editorial

AI assistants work best with code in Git and automated build/test loops that check changes immediately.

Risks and counterarguments – an honest look

MainframeGuru editorial
  • Culture: ANZ’s Core Banking Engineering Lead says in the IBM case study: “Whilst the technical changes were significant, the cultural shift was paramount.” Training teams and bringing them along is part of the project.
  • Loss of proven processes: library managers bundle promotion, approvals and emergency procedures. These must be deliberately recreated in the new world.
  • Character sets: EBCDIC content with non-printable or non-round-trippable characters needs a strategy (IBM Z DevOps Guide).
  • Security: code leaves the z/OS security domain; permissions, secrets and runner access must be designed carefully.
  • Big bang: according to the IBM Expert Labs success stories, Atruvia and dwpbank migrated in tranches of application bundles (see Migrations).
