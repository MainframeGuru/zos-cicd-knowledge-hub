What does CI/CD on z/OS mean?

MainframeGuru editorial

Continuous integration and continuous delivery (CI/CD) means that every change to the source code is automatically built, checked and delivered reproducibly all the way to the target environment. On the mainframe, this replaces traditional library manager processes that are often decades old – or complements them step by step. A typical chain looks like this:

  1. Git (source code)
  2. CI orchestration
  3. Dependency-based build
  4. Quality & security
  5. Unit/integration test
  6. Artifact repository
  7. Deployment & evidence

Important: Git alone is not a lifecycle. Build, tests, approvals, deployment and traceability have to be designed deliberately.

The building blocks at a glance

MainframeGuru editorial

Source control

Git as the single source of truth – or synchronized with an existing library manager during a transition.

Build

Dependency-based builds that compile what changed and what it affects – or existing JCL builds, triggered from the pipeline.

Orchestration

A CI server or pipeline service that reaches z/OS through SSH, REST APIs or a command-line interface.

Test & quality

Unit tests, integration tests against real z/OS systems and static analysis, used as quality gates.

Deployment

Automated deployment to the target environments, including deployment evidence for audits.

Developer experience

Modern IDEs with z/OS integration and AI assistants with z/OS context.
