Why CI/CD on z/OS?

MainframeGuru editorial

The reasons for switching are rarely purely technical. Usually the skills situation, company-wide standardization, speed, quality and compliance all come together. Here are the main drivers – each with publicly documented examples.

Skills · One standard: Git · Speed · Quality & testing · Compliance · Cost · AI · Risks · FAQ

1. Skills and developer experience

In the BMC Mainframe Survey 2025, millennials make up 51% and Gen Z 15% of respondents (BMC).

MainframeGuru editorial

People trained on Git, modern IDEs and pull requests find it hard to work with ISPF-centric library manager processes. Uniform tools across all platforms make knowledge transferable and shorten onboarding time.

Real-world example: according to a Legacy IT Center report (in German), UBS has trained young talent in its own programme for two decades and relies on Git, GitLab, CI/CD pipelines and code scanning so that COBOL developers can use the same tools and processes as colleagues on other platforms (Legacy IT Center).

2. One standard for the whole enterprise

MainframeGuru editorial

Git is the de facto standard for version control. Keeping mainframe code in the same system enables shared reviews, security scans, permission and audit models, and cross-platform releases.

An article by IBM Fellow Rosalind Radcliffe on Planet Mainframe argues that Git should be the authoritative source for code, pipeline definitions and configuration – rather than being permanently synchronized with a legacy library manager (Planet Mainframe). Broadcom, BMC and Rocket offer coexistence options (Endevor Bridge for Git, Code Pipeline with Git, ChangeMan Git integration) – see Migrations.

3. Speed and parallel development

  • ANZ Bank: according to the IBM case study, hotfixes previously took approximately four weeks of effort to retrofit into the SCM and deploy into non-production environments; with the CI/CD framework, hotfixes are deployed directly to production through the pipeline, and each “now only takes an hour maximum” (IBM).
  • Nedbank: build-to-production reduced from hours to around 18 minutes, deployment cycles from 2–3 months to around 3 weeks (BMC).
  • Incremental builds: dependency-based builds compile only what changed and what is affected – a BMC internal team reports a reduction from around 90 to 3 minutes (BMC).

MainframeGuru editorial

Branches instead of check-out/check-in allow several developers to work on the same program at the same time.

4. Quality through automated testing

According to IBM, IBM Test Accelerator for Z 3.0 generates and runs COBOL unit tests with AI assistance; according to BMC, BMC AMI DevX Unit Test (beta) generates test data from COBOL sources. Integration tests against real z/OS systems can be automated with the open-source framework Galasa, and Sonar documents static analysis for COBOL in SonarQube.

MainframeGuru editorial

In a pipeline, these become quality gates.

5. Compliance and traceability

MainframeGuru editorial

Regulated industries need a complete trail from the business change to the module in production. Toolchains can provide this through commit history, pull request approvals, build metadata, software bills of materials (SBOMs) and deployment evidence.

According to a guest article by IKAN on TechChannel, Git “does not manage the complete application lifecycle” (TechChannel).

6. Cost and tool landscape

The IBM case study on ANZ reports an approximately 90% licensing cost reduction compared with traditional mainframe-based SCM (IBM).

MainframeGuru editorial

New costs arise for build/deploy tools, pipeline infrastructure, migration and training.

7. AI in mainframe development

The vendors in the news section on this site have announced AI features for mainframe development, each according to its own announcement (in date order): Rocket “AI-powered code explanation” (November 2025); Broadcom a read-only MCP bridge to the Endevor inventory in beta (February 2026); IBM the Bob Premium Package for Z (July 2026), Test Accelerator for Z 3.0 (September 2026), Pipeline Automation for Z, MCP tools in Wazi Deploy 4.0 and the IBM Z Atlas public preview (October 2026); BMC the Code Pipeline MCP Server (beta, October 2026). According to the Open Mainframe Project’s session overview for GS UK Forge 2026, Broadcom introduced the Open Mainframe Project Zowe MCP Server there.

MainframeGuru editorial

AI assistants work best with code in Git and automated build/test loops that check changes immediately.

Risks and counterarguments

ANZ’s Core Banking Engineering Lead says in the IBM case study: “Whilst the technical changes were significant, the cultural shift was paramount.” (IBM)

MainframeGuru editorial

  • Culture: training teams and bringing them along is part of the project.
  • Loss of proven processes: library managers bundle promotion, approvals and emergency procedures. These must be deliberately recreated in the new world.
  • Character sets: EBCDIC content with non-printable or non-round-trippable characters needs a strategy (see code pages).
  • Security: code leaves the z/OS security domain; permissions, secrets and runner access must be designed carefully.
  • Scope of each step: moving everything at once and moving in stages need different planning for cutover, parallel operation and rollback.
